# 对外汇总隐私网关（privacy_gateway）

解决"对外汇总相减会暴露单批试封计数"的问题。本模块是独立子系统，**只使用 Python
标准库**，不改动 `backend/`（内部研究）与 `frontend/`，内部研究流程保持不变。

## 威胁模型与规则

* 冻结一个**至多 12 批**的发布集合；冻结后不可增删改，重启也不变。
* 对外只公开每批 A/B 总数；单批合格数是内部研究数据，不进入任何对外响应/页面。
* 对外只受理"任意批子集的 **A、B 两组合格数之和**"这一种汇总。
* 每条候选回答都要与**全部已公开回答组成联合整数系统**统一裁决，
  **禁止只逐条或两两检查**；任一"批×组"的可行合格数最小值与最大值相差
  **不足 2（即 width < 2）即拒绝**。
* 并发申请按**同一公开历史**串行裁决（网关内全局锁 + 仅追加事件日志），
  裁决形成确定全序；`request_id` 幂等，重试不重复发布。
* 中断恢复不遗漏任何已公开回答：事件逐行 `flush+fsync`，重放时截除末条不完整行。
* 角色权限隔离：对外令牌无法触达冻结/原数据/诊断入口；内部令牌可见真实合格数。

## 目录

| 文件 | 职责 |
|---|---|
| `models.py` | 冻结发布集、批次、回答、裁决；≤12 批、非负、合格数≤总数校验 |
| `solver.py` | 有界整数等式系统的可行性与逐变量 min/max（界传播 + 分支定界，纯标准库） |
| `store.py` | 仅追加 JSONL 事件日志，`fsync` 落盘，崩溃部分行截断自愈 |
| `gateway.py` | 冻结、幂等申请、联合裁决、并发串行化、恢复装载、联合宽度诊断 |
| `server.py` | 标准库 HTTP 服务，Bearer 双令牌角色隔离 |
| `pages/portal.html` | 对外专用页面：只显示获准值或拒绝原因，不内嵌任何原数据 |
| `scripts/seed_demo.py` | 固定 seed=42 生成 12 批演示冻结集 |
| `scripts/verify.py` | 五段 42 项联合验证（见下） |

## 联合裁决的精确降维

每条公开回答都是整批两组合计，只约束批次级变量
`z_i = a_i + b_i`，其中 `0 ≤ z_i ≤ total_a_i + total_b_i`。
因此先在至多 12 个 `z` 变量上求解联合整数可行域，再单调映射回每组：

```
a ∈ [max(0, z - total_b), min(total_a, z)]
a_min = L(z_min),  a_max = U(z_max)      # L、U 关于 z 单调
b_min = max(0, z_min - total_a),  b_max = min(total_b, z_max)
```

该降维对本系统的子集求和结构**精确无损**，把搜索空间从 24 变量降到 12 变量；
满规模 12 批、26 个密集申请的全量裁决在本机约 0.3s 完成。

## 运行

```bash
# 1) 冻结演示数据（可选；也可用内部令牌经 HTTP 冻结）
PYTHONPATH=. python -m privacy_gateway.scripts.seed_demo /tmp/gw/events.jsonl

# 2) 启动服务
EXTERNAL_TOKEN=对外令牌 INTERNAL_TOKEN=内部令牌 \
GATEWAY_STORE=/tmp/gw/events.jsonl GATEWAY_PORT=18080 \
python -m privacy_gateway.server
```

专用页面：http://127.0.0.1:18080/portal （页面不内嵌数据，数据凭对外令牌拉取）

### 接口

| 方法 路径 | 角色 | 说明 |
|---|---|---|
| `GET  /health` | 任意 | 健康与冻结状态 |
| `GET  /portal` | 任意 | 对外专用页面（无数据） |
| `GET  /api/public/batches` | 对外/内部 | 仅各批 A/B 总数 |
| `GET  /api/public/history` | 对外/内部 | 已公开回答 |
| `GET  /api/public/decisions` | 对外/内部 | 全部裁决（含拒绝原因） |
| `POST /api/public/aggregation-requests` | 对外/内部 | 申请子集两组合格数之和；获准 200，拒绝 403+原因 |
| `POST /api/internal/freeze` | 仅内部 | 冻结发布集（仅一次） |
| `GET  /api/internal/batches` | 仅内部 | 原数据，含真实合格数 |
| `GET  /api/internal/widths` | 仅内部 | 联合可行域 min/max/宽度诊断 |

申请体：`{"request_id": "req-001", "subset": ["B01", "B03"]}`。
同一 `request_id` 重试返回逐字相同的裁决且不新增事件；同 id 换子集则报错。

## 验证（要求三条联合才可反推、并发安全、公开后重启）

```bash
python privacy_gateway/scripts/verify.py
```

五段共 **42 项断言，全部通过**：

* **A 三条联合才可反推**：构造 3 批场景，前两条回答下所有变量宽度 ≥2（朴素
  两两检查会误放行第三条，A3 显式证明），而三条联合把 `B01-A/B` 宽度压到 <2，
  服务联合裁决拒绝第三条与全集合申请；拒绝不发布候选值，公开历史不变。
* **B 并发分别安全**：固定到达全序的并发裁决与串行参考逐请求一致；无重复发布、
  无重复事件；并发重试不新增；合并后公开系统全部宽度仍 ≥2；幂等键滥用被拒。
* **C 公开后重启**：跨进程重建冻结集/裁决/公开回答，值逐字一致；重启后幂等
  重试不新增；二次冻结被拒。
* **D 中断恢复**：截断模拟部分写入，完整公开回答一条不丢，日志自愈后可继续受理。
* **E 角色权限隔离**：无/未知令牌 401；对外令牌对冻结/原数据/诊断入口一律 403；
  公开接口无合格数字段；专用页面不含任何原数据；拒绝经 403+原因返回。
